# RenderPhoenix — Developer & Agent System Architecture Guide

Welcome to the **RenderPhoenix** codebase. This document is the primary reference for AI agents, developers, and contributors working on the website, project portfolio, editorial devlogs, and digital assets.

---

## 1. Project Overview & Studio Identity

**RenderPhoenix** is an independent interactive creative studio from Bangladesh founded in 2019 (originally *Minehutt*, renamed in 2021). The studio creates:
- Standalone indie video games (Unreal Engine 5, Unity)
- 3D environments and level architecture (Blender)
- Real-time game assets, vehicles, and modular add-ons
- Interactive web tools, technical art, and simulation prototypes (e.g., NASA Space Apps 2025 regional award-winning lunar habitat simulator)

**Primary Website**: [renderphoenix.com](https://renderphoenix.com)  
**Host & Deployment**: GitHub Pages with custom domain via `CNAME`  
**Core Technologies**: Python SSG (`build_site.py`), Vanilla CSS (Tokens), Vanilla JavaScript, Semantic HTML5, GitHub Flavored Markdown.

## 3. Build & Compilation Engine (`builder/` & `build_site.py`)

The website utilizes a standalone, dependency-free, modular Python static site generator located in the `builder/` package and invoked via `build_site.py`.

### Architecture Modules:
1. **`builder.config.Config`**: Centralized configuration, base URLs, directory paths, and static page definitions.
2. **`builder.loaders.ContentLoader`**: Parses YAML frontmatter, loads project collections from `_projects/`, blog posts from `_posts/`, and metadata from `_data/`.
3. **`builder.markdown.MarkdownParser`**: Converts Markdown to semantic HTML with code syntax classes, blockquotes, lists, and responsive 16:9 YouTube video players.
4. **`builder.template.TemplateEngine`**: Recursively resolves includes (`{% include %}`), wraps pages in layouts (`default`, `page`, `project`, `post`), and handles template variables and conditionals.
5. **`builder.components.ComponentRenderer`**: Renders project cards, magazine post cards, service cards, team member roster, specifications lists, and modular action buttons.
6. **`builder.seo.SEOGenerator` & `SitemapBuilder`**: Produces dynamic JSON-LD multi-entity schema graphs (`Organization`, `WebSite`, `BlogPosting`, `CreativeWork`), Open Graph/Twitter meta tags, and verified `sitemap.xml` with Google Image extensions.
7. **`builder.search.SearchIndexer`**: Indexes all content into `_site/search.json` and `_site/assets/js/search-data.js`.
8. **`builder.llm.LLMGenerator`**: Automatically generates `llms.txt` and `llms-full.txt` for AI crawlers and assistants.
9. **`builder.site_builder.SiteBuilder`**: Orchestrates the build lifecycle (clean, asset copy, project/post/page build, search index, sitemap, LLM indices).

## 4. Project Structure & Authoring Guidelines

Every project in the portfolio is defined as an individual Markdown file located in `_projects/<slug>.md`.

### Project Frontmatter Schema

```yaml
---
title: "Project Title"                      # String: Display title
slug: "project-slug"                        # String: URL slug (/work/project-slug/)
description: "Short 1-2 sentence overview." # String: Lead description & SEO meta
category: "Environment"                     # String: "Game", "Environment", "Interactive", "Add-On", "UI", "3D Model"
developer: "Tasrif Ibn Mizan"               # String: Primary author or team
date: 2021-03-16                            # Date: YYYY-MM-DD release date
status: "completed"                         # String: "completed", "in-development", "prototype"
version: "1.0.0"                            # String (Optional): "1.0.0", "2.0.0", "Beta", "Prototype"
platform: "Minecraft Bedrock"               # String (Optional): e.g. "Unreal Engine 5", "Web & 3D", "Bedrock & Java"
downloads: "285.1K+"                        # String (Optional): Community download metric if applicable
cover_image: "/assets/images/projects/..."  # String: Path to cover banner image
featured: true                              # Boolean: If true, highlighted on homepage/top of /work/
award: "Regional Runner-Up"                 # String (Optional): Award or milestone badge

# Modular Action Buttons (One or more can be configured):
download_links:                             # Array of custom download buttons
  - label: "Download for Bedrock"
    url: "https://example.com/bedrock"
    primary: true                           # Boolean (Optional): Highlight as primary button
  - label: "Download for Java"
    url: "https://example.com/java"

github_url: "https://github.com/org/repo"   # String (Optional): Displays GitHub button with SVG Octocat icon
demo_url: "https://demo.example.com"        # String (Optional): "Launch Live Demo" button
docs_url: "https://docs.example.com"        # String (Optional): "Documentation" button
mcpedl_url: "https://mcpedl.com/..."        # String (Optional): Legacy fallback link

technologies:                               # List of tools/technologies used
  - "Unreal Engine"
  - "Blender"
  - "C++"
tags:                                       # Filter and search tags
  - "gamedev"
  - "environment"
---
```

### Project Body Formatting Rules:
- **Lead Section**: Provide 1-2 introductory paragraphs highlighting the concept, mechanics, and tools.
- **YouTube Embeds**:
  - Direct video embed: `![youtube:Showcase Trailer](https://www.youtube.com/watch?v=VIDEO_ID)`
  - Direct URL auto-convert: Pasting `https://youtu.be/VIDEO_ID` on its own line will auto-render a responsive 16:9 iframe.
- **Screenshots & Media**:
  - Always use descriptive captions: `![Exterior Courtyard Overview](/assets/images/projects/name/screenshot.png)`
  - Images automatically render with figure captions and hover styling.
- **Feature Sections**: Use semantic `###` headings for sub-systems (e.g. `### Gameplay Mechanics`, `### Technical Specifications`, `### Installation & Setup`).

## 5. Blog Post Structure & Editorial Guidelines

All articles, retrospectives, and studio devlogs are located in `_posts/` with the strict filename convention:  
`YYYY-MM-DD-post-title-slug.md`

### Blog Post Frontmatter Schema

```yaml
---
layout: post                                # Must be 'post'
title: "Article Title Here"                 # String: Full headline
description: "1-2 sentence summary."        # String: Subheadline and SEO description
date: 2026-08-22 00:00:00 +0600             # DateTime: ISO/Jekyll timestamp
categories:                                 # List: Primary categories (e.g., studio, devlog, announcement)
  - studio
  - news
tags:                                       # List: Tag chips displayed at bottom of article
  - renderphoenix
  - gamedev
  - unreal-engine
author: "Cristo Parker"                     # String: Author name
image: "/assets/images/blog/cover.png"      # String: Path to hero header graphic
featured: true                              # Boolean: If true, renders as main featured story on /blog/
---
```

### Blog Body Formatting Rules:
- **Structure**:
  1. Compelling lead paragraph introducing the announcement or technical topic.
  2. Thematic sections divided with `## Section Title` and `### Subsection`.
  3. Visual diagrams, code snippets, or asset screenshots embedded where appropriate.
  4. Closing conclusion or future roadmap callout.
- **Code Blocks**: Specify language identifier (e.g., ```` ```cpp ```` or ```` ```python ````).
- **Blockquotes / Callouts**: Use `>` for important takeaways or quotes.

## 6. Design System & CSS Architecture

The visual identity uses a sleek, dark cyber-aesthetic inspired by creative technology and real-time engines.

### Key CSS Files:
- **`variables.css`**: Defines CSS custom properties:
  - Backgrounds: `--color-bg` (`#090A0F`), `--color-surface` (`#10121A`), `--color-surface-elevated` (`#171A26`)
  - Accents: `--color-ember` (`#FF4E00`), `--color-cyan` (`#00F0FF`), `--color-purple` (`#8A2BE2`)
  - Text: `--color-text` (`#E2E8F0`), `--color-text-muted` (`#94A3B8`)
  - Border & Glass: `--color-border` (`#1E2235`), `--glass-bg`, `--glass-border`
- **`components.css`**: Button styles (`.btn-primary`, `.btn-secondary`, `.btn-github`), cards (`.magazine-card`, `.project-card`), badges (`.cat-badge`), and sidebar widgets.
- **`typography.css`**: Font families (`Space Grotesk` for display headings, `Inter` for body, `JetBrains Mono` for code).

## 7. Client-Side JavaScript Features

1. **Global Controller (`assets/js/main.js`)**:
   - Handles sticky navbar with glassmorphism blur effect on scroll.
   - Controls mobile hamburger menu drawer animation.
   - Smooth scroll handling for internal anchor tags.
2. **Search Controller (`assets/js/search.js`)**:
   - Opens overlay search modal on `Ctrl + K` / `Cmd + K` or search icon click.
   - Filters `window.SEARCH_INDEX` (generated from `_site/assets/js/search-data.js`) in real-time.
   - Displays combined matching articles and projects with instant previews.
3. **Category Filtering (`assets/js/filter.js`)**:
   - Controls client-side tab switching on `/work/` and `/blog/` with zero page reload.

## 8. Common Agent Workflows & Commands

### 1. Build the Entire Static Site
Whenever any Markdown file, layout template, CSS, JS, or data file is modified, compile the site:
```bash
python3 build_site.py
```

### 2. Run Local Development Server
To verify rendering, links, search, and responsive layout on localhost:
```bash
python3 -m http.server 4000 --directory _site
```
Then navigate to `http://localhost:4000/`.

### 3. Adding a New Project
1. Create `_projects/<slug>.md`.
2. Add comprehensive frontmatter (`title`, `slug`, `category`, `developer`, `date`, `version`, `platform`, `download_links`, `cover_image`, `tags`).
3. Add gameplay/system documentation in Markdown with media screenshots.
4. Run `python3 build_site.py`.
5. Verify `_site/work/<slug>/index.html`.

### 4. Adding a New Devlog / Post
1. Create `_posts/YYYY-MM-DD-<slug>.md`.
2. Add required frontmatter (`layout: post`, `title`, `description`, `date`, `categories`, `tags`, `author`, `image`).
3. Write article copy with proper headings.
4. Run `python3 build_site.py`.
5. Verify `_site/blog/<slug>/index.html`.

## 9. Quality & Integrity Standards for AI Agents
- **Preserve Links**: Keep internal relative links consistent (`/work/<slug>/`, `/blog/<slug>/`).
- **No Broken Media**: Ensure all images referenced in frontmatter and Markdown exist in `assets/images/`.
- **Clean Builds**: Always execute `build_site.py` after editing content to verify exit code `0`.
- **Maintain llms.txt**: When adding major studio milestones or shifting core capabilities, update `llms.txt` to keep AI assistant metadata aligned with the live site.
